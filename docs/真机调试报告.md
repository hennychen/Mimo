### 2. 相机兼容性处理

#### 问题诊断
```
CameraException(IllegalArgumentException, 
  java.lang.IllegalArgumentException: 
  androidx.camera.core.internal.CameraUseCaseAdapter$CameraException: 
  java.lang.IllegalArgumentException: 
  No supported surface combination is found for camera device - Id : 0/1.
  May be attempting to bind too many use cases.
)
```

**根本原因**: 
- Flutter camera 插件底层使用 CameraX
- CameraX 自动绑定 3 个用例: Preview + ImageCapture + ImageAnalysis
- Redmi K40S 的 Camera2 API 不支持这种多用例组合
- 这是硬件/驱动层面的限制

#### 实施的解决方案

##### 2.1 改进的错误处理
**文件**: `lib/data/repositories_impl/camera_repository_impl.dart`

```dart
try {
  _controller = camera.CameraController(
    selectedCamera,
    camera.ResolutionPreset.low,
    enableAudio: false,
  );
  
  await _controller!.initialize();
  _isInitialized = true;
  print('✅ Camera initialized successfully');
} catch (cameraError) {
  print('❌ Camera initialization failed: $cameraError');
  print('⚠️ Using mock camera mode for development');
  _isInitialized = false;
  rethrow;
}
```

##### 2.2 服务层降级方案
**文件**: `lib/application/services/frame_processing_service.dart`

```dart
} catch (e) {
  print('❌ Failed to start frame processing: $e');
  print('⚠️ Application will continue in limited mode');
  
  // 即使相机失败,也允许应用继续运行
  _state = FrameProcessingState.paused;
}
```

##### 2.3 友好的用户提示
**文件**: `lib/presentation/pages/calibration_page.dart`

添加了相机失败时的 UI 提示:
- 清晰的错误图标和说明
- 解释设备兼容性问题
- 提供替代方案建议
- "进入主页"按钮允许跳过校准

## ❌ 已知限制

### CameraX 表面组合不兼容

**影响范围**:
- 所有基于 Flutter camera 包的应用
- Redmi K40S 及类似硬件配置的设备
- 前置和后置摄像头均受影响

**技术细节**:
```
设备: munch (Redmi K40S)
Camera ID: 0 (后置), 1 (前置)
Hardware Level: INFO_SUPPORTED_HARDWARE_LEVEL_3
尝试绑定的用例:
  - Preview (320x240, NV21)
  - ImageCapture (320x240, JPEG)
  - ImageAnalysis (未激活)
结果: No supported surface combination
```

**无法通过以下方式解决**:
- ❌ 降低分辨率 (已尝试 low/VGA)
- ❌ 切换摄像头 (前后置都失败)
- ❌ 升级 camera 包版本
- ❌ 修改 CameraX 配置

## 🔧 推荐的后续方案

### 方案 1: 更换测试设备 (推荐)

**兼容性更好的设备**:
- Google Pixel 系列
- Samsung Galaxy S/Note 系列
- OnePlus 设备
- 大多数 2022+ 的中高端设备

**优势**:
- 无需修改代码
- 完整功能测试
- 真实用户体验

### 方案 2: 使用 Android 模拟器

**设置步骤**:
```bash
# 创建 AVD
flutter emulators --create [--name xyz]

# 启动模拟器
flutter emulators --launch <emulator_id>

# 运行应用
flutter run -d <emulator_id>
```

**优势**:
- 开发环境即可测试
- 可模拟不同设备配置
- 便于调试

**劣势**:
- 性能不如真机
- 相机模拟有限

### 方案 3: 实现原生 Camera2 API

**工作量**: 高 (预计 2-3 周)

**实现要点**:
```java
// Android 原生代码
CameraDevice.StateCallback stateCallback = new CameraDevice.StateCallback() {
    @Override
    public void onOpened(@NonNull CameraDevice camera) {
        // 只绑定 Preview 用例
        CaptureRequest.Builder requestBuilder = 
            camera.createCaptureRequest(CameraDevice.TEMPLATE_PREVIEW);
        // 手动控制图像流
    }
};
```

**优势**:
- 完全控制相机行为
- 可以只用单个用例
- 最佳性能

**劣势**:
- 需要大量原生代码
- 维护成本高
- 跨平台复杂性

### 方案 4: 使用替代相机包

**候选方案**:
1. **camerawesome** (^2.5.0)
   - 更灵活的配置
   - 内置 UI
   - 但仍基于 CameraX

2. **mobile_scanner**
   - 专注于条码扫描
   - 轻量级

3. **camera_camera**
   - 简化版 camera 包

**注意**: 大多数替代方案仍使用 CameraX,可能遇到相同问题。

### 方案 5: 接受当前限制 (短期)

**适用场景**:
- MVP 阶段
- 主要展示其他功能
- 目标用户不使用此设备

**实施**:
- ✅ 已完成
- 应用在有限模式下运行
- 用户可以跳过校准
- 清晰的用户提示
